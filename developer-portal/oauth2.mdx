OAuth2 lets a person give your service access to their Fractura account. Fractura uses the authorization code flow. Your service gets an access token and calls the API as that person, with the scopes that the person approved.

## Set up the application

1. Open the application in the [developer portal](https://frta.dev).
2. Open **Capabilities**. Turn on **User OAuth**, **Workspace OAuth**, or both. Save.
3. Open **OAuth2**.
4. Under **Redirects**, add each URL that Fractura can send the person back to. Save.
5. Select **Reset secret**. Copy the client secret. The portal shows it only one time.

A redirect URI must use `https`. For local tests, `http` is allowed for `localhost`, `127.0.0.1`, and `[::1]`. An application can have 10 redirect URIs.

The client id is the application id.

<Caution>

Keep the client secret on your server. Do not put it in a browser app or a mobile app.

</Caution>

## Scopes

| Scope | Gives access to | Capability |
| --- | --- | --- |
| `identify` | The user id, username, and public profile. | `user_oauth` |
| `identify.email` | The email address. Adds `identify`. | `user_oauth` |
| `workspaces.list` | The workspaces that the person selects on the consent screen. | `workspace_oauth` |
| `bot` | Installs the bot. Read [Install a bot](/docs/install-a-bot). | A bot user |

## 1. Send the person to Fractura

Send the person to this URL:

```text
https://app.fractura.org/oauth2/authorize?response_type=code&client_id=APPLICATION_ID&redirect_uri=REDIRECT_URI&scope=identify&state=STATE
```

| Parameter | Description |
| --- | --- |
| `response_type` | `code`. |
| `client_id` | The application id. |
| `redirect_uri` | One of your redirect URIs. It must match exactly. |
| `scope` | The scopes, separated by spaces. |
| `state?` | A random value. Fractura sends it back to you. Always send it. |

The **OAuth2** page can make this URL for you. Select the scopes and a redirect URI, then select **Copy URL**. Add `state` yourself.

<Caution>

Make a new random `state` for each request and store it in the session of the person. When the person comes back, compare the values. Fractura does not check `state` for you.

</Caution>

## 2. Read the code

The person approves the request. Fractura then sends the person to your redirect URI:

```text
https://example.com/callback?code=CODE&state=STATE
```

If the person selects **Cancel**, the URL has `error=access_denied` instead of `code`.

The code is valid for 10 minutes. You can use it only one time.

## 3. Get a token

<Endpoint method="POST" path="/oauth2/token" />

Send the body as JSON or as `application/x-www-form-urlencoded`. Put the client id and the client secret in the body. Fractura does not accept HTTP Basic authentication.

| Field | Description |
| --- | --- |
| `grant_type` | `authorization_code`. |
| `code` | The code from step 2. |
| `redirect_uri` | The same redirect URI as in step 1. |
| `client_id` | The application id. |
| `client_secret` | The client secret. |

<CodeGroup>

```javascript
const response = await fetch("https://fractura.org/api/oauth2/token", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    grant_type: "authorization_code",
    code,
    redirect_uri: "https://example.com/callback",
    client_id: process.env.CLIENT_ID,
    client_secret: process.env.CLIENT_SECRET,
  }),
});

const token = await response.json();
```

```python
async with aiohttp.ClientSession() as http:
    async with http.post("https://fractura.org/api/oauth2/token", json={
        "grant_type": "authorization_code",
        "code": code,
        "redirect_uri": "https://example.com/callback",
        "client_id": os.environ["CLIENT_ID"],
        "client_secret": os.environ["CLIENT_SECRET"],
    }) as response:
        token = await response.json()
```

</CodeGroup>

The response:

```json
{
  "access_token": "fra_...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "...",
  "scope": "identify"
}
```

The access token is valid for 1 hour. The refresh token is valid for 30 days.

## 4. Call the API

Send the access token with the `Bearer` prefix:

```http
GET /api/oauth2/userinfo HTTP/1.1
Host: fractura.org
Authorization: Bearer fra_...
```

| Route | Scope | Returns |
| --- | --- | --- |
| `GET /oauth2/userinfo` | `identify` | `id`, `username`, `displayName`, `discriminator`, `avatarHash`, `flags`, `scopes`, and `email` with `identify.email`. |
| `GET /users/@me` | `identify` | The same data as `/oauth2/userinfo`. |
| `GET /oauth2/workspaces` | `workspaces.list` | The selected workspaces. Each has `id`, `name`, `status`, `tier`, and `role`. |

Other routes do not accept OAuth2 tokens.

## Refresh a token

Send `grant_type` `refresh_token` to the token route:

| Field | Description |
| --- | --- |
| `grant_type` | `refresh_token`. |
| `refresh_token` | The refresh token. |
| `client_id`, `client_secret` | Your client credentials. |
| `scope?` | A smaller set of the granted scopes. |

The response contains a new access token and a new refresh token. The old refresh token stops working. Store the new one.

## Revoke a token

<Endpoint method="POST" path="/oauth2/revoke" />

Send `client_id`, `client_secret`, and `token` (an access token or a refresh token). Fractura removes the connection between the person and your application. All tokens of that connection stop working. The response has status `204`.

## Errors

The token route returns status `401` for all errors: a wrong secret, a used or expired code, or a revoked connection.
